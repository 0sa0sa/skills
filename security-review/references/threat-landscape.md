# 脅威ランドスケープ・サイバー戦

国家支援型攻撃、APT、脅威インテリジェンス、帰属分析、サプライチェーン攻撃の脅威モデルに関わる観点を見る。

## チェックリスト

### 1. 脅威インテリジェンスの帰属(attribution)主張を鵜呑みにせず、根拠となる前提と証拠を要求しているか
- **なぜ重要か**: 帰属は推論であり演繹的証明ではない。CrowdStrikeの「Putter Panda」報告は帽子の写真等の状況証拠のみで高確度帰属を発表した例がある。帰属を誤ると対応(制裁・報復・法的措置)の方向性そのものを誤る。
- **出典**: Inside Cyber Warfare 3rd Ed, 第2章 p.20-24

### 2. 単一ベンダー・単一情報源による国家主体への帰属を、複数の独立した情報源で裏付けているか
- **なぜ重要か**: Moonlight Maze(1999年)は勤務時間パターン等の弱い状況証拠のみで、ロシア特定部隊への確定帰属が一度もなされなかった。
- **出典**: Inside Cyber Warfare 3rd Ed, 第2章 p.19

### 3. マルウェアの「排他的使用」仮定(同一マルウェア=同一攻撃者という前提)を過信していないか
- **なぜ重要か**: XAgent/X-Tunnel等は2012年から複数主体に使い回され、ウクライナGURも押収マルウェアを改変再利用している。
- **出典**: Inside Cyber Warfare 3rd Ed, 第2章 p.25-26

### 4. 脅威モデルを定義する際、想定する攻撃者レベル(機会主義的(opportunistic)な攻撃者〜信頼された内部者)を明示し、国家支援型の攻撃者(state-level actor)への防御を対象に含めるか対象外とするかを明確にしているか
- **なぜ重要か**: 全ての脅威アクターへの完全防御は非現実的であり、想定範囲を誤ると過剰投資または致命的な防御不足のいずれかに陥る。
- **出典**: Zero Trust Networks 2nd Ed, 第2章 p.24-28

### 5. ENISA Threat Landscape等の最新の脅威インテリジェンスレポートを定期的にレビューし、自組織の業種固有の脅威(サプライチェーン標的化等)を踏まえているか
- **なぜ重要か**: 脅威の全体像は年々変化し、レビューを怠ると防御優先度を誤る。
- **出典**: Security Architecture for Hybrid Cloud, 第3章

### 6. MITRE ATT&CK、Cyber Kill Chain、OSC&R等の脅威分析・脅威インテリジェンスフレームワークを活用しているか
- **なぜ重要か**: 実世界の攻撃者(APTグループ含む)の手口に基づく体系的な脅威抽出・追跡が可能になる。
- **出典**: Software Supply Chain Security, 第4章 p.57

### 7. 脅威アクターを「外部×権威あり/なし」「内部×権威あり("honest but curious")/なし」「過失行為者」という複数パターンに分類し、それぞれに応じた検知優先度を設計しているか
- **なぜ重要か**: 単一の攻撃者像だけを前提にすると、内部者の過失や「善意だが詮索好きな」内部者由来の漏洩など他のパターンの検知が抜け漏れる。
- **出典**: Security Architecture for Hybrid Cloud, 第6章

### 8. APT(Advanced Persistent Threat)のように長期潜伏し情報収集を行う攻撃者を想定した監視を行っているか(短期的な攻撃検知だけに依存していないか)
- **なぜ重要か**: 短期的攻撃検知の仕組みだけでは、長期潜伏型の侵害を見逃す。
- **出典**: Security as Code, p.36-37

### 9. サプライチェーン経由の侵入からOT(制御システム)への破壊工作に至る攻撃チェーンを脅威モデルに含めているか
- **なぜ重要か**: Gazprom事例ではサプライヤーへのフィッシング侵入から信頼関係の悪用を経て、パイプライン圧力制御の改ざん・爆発に至った。
- **出典**: Inside Cyber Warfare 3rd Ed, 第6章 p.102

### 10. SolarWindsのようなビルドプロセス・依存関係への完全性侵害(サプライチェーン攻撃)を自組織の脅威モデルに明示的に組み込み、SLSA等のフレームワークで脅威エントリポイントを評価しているか
- **なぜ重要か**: SolarWinds攻撃は検知まで約14ヶ月かかり18,000顧客がリスクに晒された。3CX事件では二重のサプライチェーン攻撃構造も確認されており、単発の防御では不十分。
- **出典**: Software Supply Chain Security 第5章 p.81; Zero Trust Networks 2nd Ed 第7章 p.138-139; Cloud Native Security Cookbook 第10章 p.484

### 11. サプライチェーン攻撃は外部からの侵入だけでなく、正規のメンテナが長期間信頼を積み重ねた上でバックドアを仕込むケース(ソーシャルエンジニアリング的サプライチェーン攻撃)もあることを脅威モデルに含めているか
- **なぜ重要か**: XZ Utilsバックドア事件は、信頼されたメンテナ自身がコードを操作した例として紹介されており、外部侵入の検知手法だけでは防げない。
- **出典**: Identity Security for Software Development, 第9章

### 12. 実際のサプライチェーン攻撃事例(Codecov、SolarWinds、XZ Utils、Log4j等)をベースにしたインシデント想定訓練を実施しているか
- **なぜ重要か**: これらは実際に数千〜数万組織に影響した代表的な侵害であり、攻撃パターンの再発防止策を学ぶ具体的な材料になる。
- **出典**: Identity Security for Software Development, 第1章・第9章

### 13. 軍・政府の機密取扱者に対し、外国政府の管轄下にあるアプリ(TikTok等)の業務利用を禁止または利用端末を限定しているか
- **なぜ重要か**: TikTokは常時監視デバイスとなり得、外国情報機関による収集は「合法的なスパイ行為」に相当すると著者は指摘している。
- **出典**: Inside Cyber Warfare 3rd Ed, 第5章 p.81-83

### 14. 国家代理組織(民間軍事会社・トロール工場等)が軍事行動と偽情報工作を連動させる「enmeshed warfare」シナリオを脅威モデルに含めているか
- **なぜ重要か**: ワグネル・グループとインターネット・リサーチ・エージェンシーは同一オーナー(Prigozhin)の下、ウクライナ・シリア・マリの全事例で軍事力と情報戦が一体運用されていた。
- **出典**: Inside Cyber Warfare 3rd Ed, 第5章 p.65-79

### 15. 自組織に関連する第三者(資金提供元・支援団体・NGO等)を標的とした信用毀損攻撃への備えがあるか
- **なぜ重要か**: White Helmetsの資金調達責任者は偽情報の標的となり自殺に追い込まれた。資金源を狙う攻撃は国家主体の情報戦において最も効果的な手法の一つとされる。
- **出典**: Inside Cyber Warfare 3rd Ed, 第5章 p.73, 76

### 16. 自組織や個人がサイバー戦争に志願的に参加する場合、Direct Participant in Hostilities(DPH)認定基準に基づくリスク(合法的な軍事標的化の可能性)を理解・評価しているか
- **なぜ重要か**: 一定の実害を引き起こす民間ハッカーは合法的な軍事標的(殺害対象)となりうる。英国人ハッカーJunaid Hussainは2015年にドローン攻撃で殺害された。
- **出典**: Inside Cyber Warfare 3rd Ed, 第4章 p.57-60

### 17. サボタージュ(国家主体による物理破壊工作)の戦略的効果を過大評価せず、検知より回復力(resilience)・冗長性を重視した防御戦略になっているか
- **なぜ重要か**: Stuxnet後もイランの遠心分離機は2022年に4000基まで増加しており、サボタージュの長期的な費用対効果には疑問が呈されている。
- **出典**: Inside Cyber Warfare 3rd Ed, 第6章 p.111-113

### 18. 量子コンピュータによる将来的な暗号解読リスク(「今収集し後で復号する」= harvest-now-decrypt-later攻撃)を認識し、PQC(耐量子暗号)への移行計画を検討しているか
- **なぜ重要か**: 国家主体による長期的な傍受・保存・将来復号という脅威シナリオが想定されており、現行の暗号方式も将来の量子コンピュータの実用化により解読される可能性がある。
- **出典**: Zero Trust Networks 2nd Ed, 第12章 p.287-289

### 19. ランサムウェアの類型(クリプトランサムウェア、リークウェア/ドックスウェア、ロッカーランサムウェア、RaaS)ごとに対策が整理されているか
- **なぜ重要か**: 攻撃の性質によって対応すべき防御・復旧策が異なる。ランサムウェアは脅威の中でも最大セグメントとされており、類型を区別しないと対応の優先順位を誤る。
- **出典**: Security as Code, p.37-38

### 20. 高価値資産に対する物理的強要(coercion)シナリオを想定し、単独アクセス不可のグループ認可(複数人の承認が必要な仕組み)を適用しているか
- **なぜ重要か**: 国家主体は従業員本人を物理的に強要してアクセスさせる手段をとりうり、技術的な認証・認可統制だけでは防げない。
- **出典**: Zero Trust Networks 2nd Ed, 第10章 p.250-251

### 21. 特権昇格・横移動のシナリオ(クラウド→Azure AD/Entra ID→オンプレAD侵入等、国家レベル攻撃者のTTPを模した攻撃)を定期的にレッドチーム演習しているか
- **なぜ重要か**: 実際の模擬攻撃では、クラウド側の弱い認可設定を起点にオンプレミスの中核ディレクトリまで横移動できることが示されており、机上の脅威モデルだけでは見逃す実装上の穴を検証できる。
- **出典**: Zero Trust Networks 2nd Ed, 第10章 p.242-244

### 22. データ資産を機密性・完全性・可用性の観点で分類し、処理結果(メタデータ)自体が元データより機密度の高い「crown jewels」になりうることを認識しているか
- **なぜ重要か**: 元データだけを分類・保護する発想では、複数のデータを突合・集約した処理結果(メタデータ)がより機密性の高い情報(行動パターンや組織構造の推測等)を露出するリスクを見落とす。
- **出典**: Security Architecture for Hybrid Cloud, 第5章
