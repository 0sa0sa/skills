# 安全性・ガードレール・セキュリティ

プロンプトインジェクション対策、多層ガードレール、最小権限、PII保護、権限承認フローなど、安全性・セキュリティに直結する設計を見る。

## チェックリスト

### 1. プロンプトインジェクション対策として、アクションセレクター化・実行計画の事前固定・Map-Reduce的分離・デュアルLLM構成・コード実行への切替・コンテキスト最小化などの具体的な防御手法を実装しているか
- **なぜ重要か**: 外部入力やツール経由の文書・Web取得結果に悪意ある指示が埋め込まれると、エージェントが意図しない権限昇格や情報漏洩・不正操作を実行してしまうため。
- **出典**: 生成AIデザインパターン 7章 P21(チェックリスト44)

### 2. 入力検証・出力フィルタ・振る舞い制約・ツール利用制限・外部モデレーションAPI・人間監視といった複数レイヤーのガードレール、または入力・出力・検索・ツール呼び出しパラメータの4箇所すべてにガードレールを組み合わせているか
- **なぜ重要か**: 単一レイヤーの防御は突破され得るため、多層防御(defense in depth)によって各経路からの攻撃・誤動作を防ぐ必要がある。
- **出典**: Agentic Design Patterns Ch18 Guardrails(チェックリスト62); 生成AIデザインパターン 9章 P32(チェックリスト47)

### 3. 軽量・安価なモデルを一次/二次の高速セーフティチェックとして用い、コスト効率の良いガードレール運用になっているか
- **なぜ重要か**: すべてのリクエストに高コストなモデルで安全性判定を行うとコスト・レイテンシが増大するため、安価なモデルによる高速な一次フィルタリングで全体のガードレール運用を効率化する必要がある。
- **出典**: Agentic Design Patterns Ch18 Guardrails(チェックリスト63)

### 4. 「ignore previous rules」等の既知パターンを含むジェイルブレイク想定テストや敵対的入力セットでの安全性評価を、本番公開前・継続的に実施しているか
- **なぜ重要か**: 既知の脱獄・敵対的プロンプティング手法への耐性を検証しないと、ガードレールが実運用で容易に迂回されてしまう。
- **出典**: Agentic Design Patterns Ch18 Guardrails(チェックリスト64), Ch21 Exploration(チェックリスト84); 実践LLMアプリケーション開発 10章周辺(チェックリスト44)

### 5. エージェントの権限が最小権限の原則に従い、乗っ取られた際の被害範囲(blast radius)を限定する設計になっているか
- **なぜ重要か**: 過剰な権限を持つエージェントが乗っ取られると、その権限の分だけ被害が拡大するため、権限を必要最小限に絞ることが被害抑制の基本になる。
- **出典**: Agentic Design Patterns Ch18 Guardrails(チェックリスト68)

### 6. 副作用のあるツール実行について、誰の権限でその操作が実行されるのかが明確に定義されているか
- **なぜ重要か**: 実行者・権限の帰属が曖昧だと、なりすましや意図しない操作・責任の所在不明な事故が起きやすい。
- **出典**: Agentic Design Patterns Ch5 Tool Use(チェックリスト17)

### 7. ツール呼び出し引数に含まれるユーザーIDをセッション状態と突き合わせて検証し、なりすまし・セッションハイジャックを防いでいるか
- **なぜ重要か**: LLMが生成した引数をそのまま信用すると、悪意あるプロンプトによって他ユーザーの情報へのなりすましアクセスが可能になる。
- **出典**: Agentic Design Patterns Ch18 Guardrails(チェックリスト67)

### 8. MCP等のクライアント-サーバ間通信において、認証・認可(ロール分離)を明示的に実装しているか
- **なぜ重要か**: 認証・認可のない接続は、不正なサーバやクライアントによる機密データの漏洩・不正操作を許してしまう。
- **出典**: Agentic Design Patterns Ch10 MCP(チェックリスト35); 生成AIデザインパターン 7章 P21(チェックリスト45)

### 9. 精密計算やコード実行はサンドボックス化された環境で行っているか
- **なぜ重要か**: 生成されたコードや精密計算をそのまま実行すると任意コード実行や意図しない副作用のリスクがあるため、サンドボックス化された環境で実行する必要がある。
- **出典**: Agentic Design Patterns Ch5 Tool Use(チェックリスト15)

### 10. サンドボックスOS自体の脆弱性がホストアクセスを許してしまう可能性まで考慮し、対策しているか
- **なぜ重要か**: サンドボックス自体に脆弱性があると、そこを突いてホスト環境へ侵入される経路になり得るため、サンドボックスの外側の防御も見落としてはならない。
- **出典**: 生成AIデザインパターン 7章 P22(チェックリスト46)

### 11. エアギャップ要件がある場合、クラウドAPIでなくローカル/オンプレモデルの採用を検討したか
- **なぜ重要か**: 機密性・規制上の理由でデータを外部に出せない環境では、クラウドLLM APIの利用自体がセキュリティ要件に違反するため、オンプレ・ローカルモデルという選択肢を検討する必要がある。
- **出典**: 生成AIデザインパターン 1章(チェックリスト54)

### 12. Webエージェントが取得したコンテンツや、生成したコンテンツをUIに表示・実行する前にサニタイズしているか(間接プロンプトインジェクションやブラウザでの悪意コード実行の対策)
- **なぜ重要か**: 外部ページやツール出力に埋め込まれた悪意ある指示・コードがそのまま解釈・実行・表示されると、意図しない動作や攻撃を引き起こす。
- **出典**: 実践LLMアプリケーション開発 10章(チェックリスト43); Agentic Design Patterns Ch18 Guardrails(チェックリスト65)

### 13. ガードレール自身が出力する判定結果(JSON等)をスキーマ検証しているか(「ガードレールのガードレール」)
- **なぜ重要か**: 安全性判定の出力自体が壊れた形式で返ると、後続のフィルタ処理が正しく機能せず防御が無力化する。
- **出典**: Agentic Design Patterns Ch18 Guardrails(チェックリスト66)

### 14. PIIや企業秘密が、ログ・キャッシュ・訓練データに混入しないよう対策しているか
- **なぜ重要か**: PIIや機密情報が保存・共有経路に混入すると、規制違反や信頼失墜、情報漏洩事故につながるため。
- **出典**: 生成AIデザインパターン 9章 P32(チェックリスト48)

### 15. 人間オペレーターに結果を見せる前に、PII等を匿名化しているか
- **なぜ重要か**: 匿名化せずに人間オペレーターへ生データを見せると、レビュー担当者を介した個人情報の不要な露出や漏洩が発生するため。
- **出典**: Agentic Design Patterns Ch13 Human-in-the-Loop(チェックリスト46)

### 16. 固有名詞等をLLMに渡す前に一般化し、PIIの漏洩経路を塞いでいるか
- **なぜ重要か**: 固有名詞をそのままLLMに渡すと、モデルの出力やログを通じてPIIが漏洩する経路が生まれるため、事前の一般化でその経路を遮断する必要がある。
- **出典**: 生成AIデザインパターン 9章 P32(チェックリスト53)

### 17. 自動補完等の機能において、ユーザー履歴が他ユーザーに漏洩しないようユーザー単位のスコープ制限をしているか
- **なぜ重要か**: ユーザー単位のスコープ制限がないと、自動補完等の機能で他ユーザーの履歴や入力内容が意図せず別のユーザーに漏洩してしまうため。
- **出典**: 生成AIデザインパターン 2章 P1(チェックリスト51)

### 18. 内部向け利用と一般公開向け利用など、利用コンテキストに応じてコンテンツモデレーション・ガードレールの強度を使い分けているか
- **なぜ重要か**: 低リスクな社内利用と高リスクな一般公開利用を同じ強度で一律に扱うと、前者では過剰な制限によるUX悪化、後者では不十分な防御による安全性低下のいずれかに傾いてしまうため。
- **出典**: 生成AIデザインパターン 9章 P32(チェックリスト49)

### 19. 厳格すぎるガードレールが情報損失やUX悪化を招いていないか、バランスを確認しているか
- **なぜ重要か**: ガードレールを厳格にしすぎると正当な利用がブロックされる情報損失やUX悪化を招くため、安全性とのバランスを継続的に確認する必要がある。
- **出典**: 生成AIデザインパターン 3-4章/9章 P11/P32(チェックリスト52)

### 20. ガードレールを攻撃手法の進化に合わせて定期的に更新する運用になっているか
- **なぜ重要か**: 攻撃手法は軍拡競争的に進化するため、静的なガードレールは時間の経過とともに無効化されるリスクがある。
- **出典**: 生成AIデザインパターン 9章 P32(チェックリスト50)

### 21. ガードレールの判定ログを記録し、攻撃パターンの特定やモデル改善に活用しているか
- **なぜ重要か**: 攻撃パターンを特定し継続的にガードレールを改善するには、判定結果のログが記録・分析可能になっている必要があるため。
- **出典**: 生成AIデザインパターン 9章/10章 P32(チェックリスト66)

### 22. A2A(エージェント間通信)のAgent CardエンドポイントをmTLS・アクセス制御で保護しているか
- **なぜ重要か**: Agent Cardのエンドポイントが保護されていないと、第三者が不正にエージェント間通信へ介入・なりすましできてしまうため。
- **出典**: Agentic Design Patterns Ch15 Inter-Agent Communication(チェックリスト54)

### 23. エージェント間の通信・関与・実行アクションを監査ログに記録しているか
- **なぜ重要か**: エージェント間の通信・関与・実行アクションが記録されていないと、問題発生時に原因や経路を追跡できなくなるため。
- **出典**: Agentic Design Patterns Ch15 Inter-Agent Communication(チェックリスト55)

### 24. コスト・レイテンシの高いプラン実行や複数ステップタスクの実行前に、人間がレビュー・承認・修正できるチェックポイントを設けているか
- **なぜ重要か**: 自律的に実行される前に人間の承認を挟むことで、誤った、または有害な行動の実行を未然に防げる。
- **出典**: Agentic Design Patterns Ch6 Planning(チェックリスト20); AIインターフェースデザイン 6章 p218(チェックリスト41)

### 25. 権限要求をリスクレベルに応じた段階的承認フローにしているか
- **なぜ重要か**: リスクレベルに関わらず同じ承認プロセスを課すと、低リスク操作まで過剰な摩擦が生じたり、逆に高リスク操作への審査が不足したりするため、リスクに応じた段階的な承認フローが必要になる。
- **出典**: AIインターフェースデザイン 6章 p194(チェックリスト42)

### 26. リスクの低い操作から「今後確認しない」永続許可オプションを提供しているか
- **なぜ重要か**: 低リスクな操作のたびに繰り返し確認を求めると、ユーザーの確認疲れ(許可疲労)を招き、重要な高リスク操作の確認まで軽視されるようになるため。
- **出典**: AIインターフェースデザイン 6章 p194(チェックリスト43)

### 27. 権限要求時に「なぜ必要か」「後で取り消せるか」を平易な言葉で一貫して説明し、OAuthスコープ等の技術詳細を理解できないユーザーにも権限の意味が伝わる表現になっているか
- **なぜ重要か**: OAuthスコープ等の技術的詳細を理解できないユーザーが、意味を分からないまま過剰な権限を許可してしまうリスクを防ぐ。
- **出典**: AIインターフェースデザイン 6章 p216/p194(チェックリスト46,47)

### 28. 金融与信や司法量刑等、最終判断権限が人間に残るべき領域でAIが実質的に代替していないか、Human-in-the-Loopでどの判断を人間がレビューすべきかを明確に線引きしているか
- **なぜ重要か**: 説明責任が求められる高リスク領域で人間の判断を省略すると、不適切な自動化による実害や責任の空白が生じる。
- **出典**: Agentic Design Patterns Ch13 Human-in-the-Loop(チェックリスト47); AIインターフェースデザイン 5章 p158(チェックリスト44)

### 29. AI生成コンテンツであることを、関連する法的要件(SB1001、EU AI法等)に沿って明示する開示を行っているか
- **なぜ重要か**: 開示義務を怠ると法的リスクとなり、利用者が生成物を人間の作成物と誤認するリスクも生じる。
- **出典**: AIインターフェースデザイン 5章 p161(チェックリスト18)

### 30. 自己改変・自己改善型エージェントをDocker等でサンドボックス化しているか
- **なぜ重要か**: 自己改変・自己改善するエージェントがサンドボックス外で動作すると、意図しないコード変更がホスト環境や他システムに直接影響を及ぼすリスクがあるため。
- **出典**: Agentic Design Patterns Ch9 Learning and Adaptation(チェックリスト30)

### 31. 自己改善ループに、停滞・逸脱を検知して停止できる非同期の監督(overseer)プロセスを設けているか
- **なぜ重要か**: 自己改善ループが暴走・停滞・意図しない方向への逸脱を起こした場合、非同期の監督プロセスがなければ誰にも検知されずに進行し続けてしまうため。
- **出典**: Agentic Design Patterns Ch9 Learning and Adaptation(チェックリスト31)

### 32. 報酬ベース学習を用いる場合、報酬ハッキングのリスクを認識し、クリッピング等の安全策を講じているか
- **なぜ重要か**: 報酬ベースで学習するエージェントは意図した目標ではなく報酬指標そのものを悪用する「報酬ハッキング」を起こす可能性があり、クリッピング等の安全策なしでは有害な行動を学習しうるため。
- **出典**: Agentic Design Patterns Ch9 Learning and Adaptation(チェックリスト32)
